# AMB82 Mini 手勢控制單一電燈

## 最新原始碼狀態

- 手勢 5（class 4）開燈、手勢 1（class 0）關燈；信心門檻 60%，僅顯示開／關類別，使用 ROI 輸入裁切。
- 每次只往指定方向轉 280ms，再輸出中立脈寬停止，無反向回程。
- 開／關指令須交替；重複指令不動馬達、不增加計數，CONTROL STATUS 顯示「已經開燈，不用啟動馬達」或「已經關燈，不用啟動馬達」。
- 有效手勢辨識成功後，板載藍色 LED 亮 1 秒；重複手勢亦亮，手動序列指令不亮。
- 手勢需持續 1 秒，兩次判定間冷卻 2 秒且清空 ROI 至少 0.5 秒；開機暫停，輸入 a 啟用、d／x 停止。
- 單方向、交替、60% 門檻及藍燈等近期修改已完成程式測試與完整編譯，尚未燒錄。尚未安裝至實體電燈開關。

## 先了解這個馬達

**GWS S35 STD 是連續旋轉伺服。PWM 決定方向與速度，不能用 `write(90)` 要求它回到 90 度。** 本程式以 50 Hz PWM、約 1500 μs 中立脈寬停止；大於／小於中立值向不同方向轉動，實際方向依安裝與校正確認。

一次動作：開燈手勢往開燈方向轉 280ms，或關燈手勢往相反方向轉 280ms，接著輸出中立脈寬停止；不自動回程。單一馬達必須搭配能從中立位置向兩側撥動翹板開關的雙向撥桿／支架。程式不能彌補不合適的機構。自鎖按鈕、觸控開關或只有單一按壓點的切換式開關，不一定能保證「手勢 5 永遠開、手勢 1 永遠關」。

定時轉動是**開迴路**，負載、電壓與摩擦會使位置逐次漂移，也無法偵測堵轉。不宜靠頂住硬限位來找原點。僅有現有設備時可完成桌上驗證，無法保證長期可靠定位或確認燈況；需要可靠定位時，後續改用定位伺服，或增加位置／限位回授。

## 接線與必要材料

除了板子與馬達，實際撥燈開關仍需要杜邦線、合適的馬達電源、伺服臂及固定支架。不要把馬達接到 3.3V 腳供電。

| 端點 | 接到 |
|---|---|
| AMB82 **D8 / PF_15** | 馬達訊號線，依馬達插頭／規格確認線序 |
| 馬達 V+ | 外接穩壓 5V 電源正極；馬達規格為 4.8–6V |
| 馬達 GND | 外接電源負極 |
| AMB82 GND | 同一外接電源負極，必須共地 |
| AMB82 USB | 正常板子供電及燒錄 |

外接 5V、2A 電源可作為起始選擇；仍要確認馬達啟動／負載時電源不掉壓。這不是已量測的堵轉電流規格。**不要將外接馬達電源正極直接併接板子的 3.3V 或 USB 供電線。** 板子輸出是 3.3V 訊號；若你的 S35 實物無法可靠接受，需補電位轉換。先用低壓、未接市電的獨立開關測試，最後只機械撥動既有開關外殼，不接觸市電配線。

## Arduino 設定與燒錄

1. 整個 `GestureLight` 資料夾放在一起，以 Arduino IDE 開啟同名 `GestureLight.ino`。
2. 選擇 **AmebaPro2 ARM (32-bits) Boards → AMB82-MINI**。本機檢查依據為 **AmebaPro2 4.1.0**。
3. 相機選實際型號；標準 AMB82 Mini 常見為 **JXF37**，請以你的模組為準。`Load NN Model from` 選 **Flash**，不需要 SD 卡。
4. 在 `Config.h` 填入 Wi-Fi SSID／密碼。class ID 已設為開燈 4、關燈 0。
5. 確認自訂模型 `yolov7_tiny.nb` 與 `.ino` 在同一資料夾。SDK 的自訂模型打包流程會依 `CUSTOMIZED_YOLOV7TINY` 選取該檔；若模型打包失敗，先檢查工具選項、檔名及 SDK 自訂模型範例。不要把尚未轉換的 `.pt` 改副檔名冒充 `.nb`。
6. 首次先拆下伺服臂、馬達電源先關閉，完成上傳。開序列監控視窗 **115200 baud**，板子訊號初始化後再供馬達電，開始空載校正。
7. Wi-Fi 連線成功後序列埠會印出 `Monitor: http://192.168.x.x`。同一 Wi-Fi 的電腦／手機瀏覽該網址；勿使用 `https://`。需要同網段且未啟用 AP client isolation。畫面是定期 JPEG 更新，瀏覽器不需要 RTSP 外掛。

本版預覽與 NN 都使用 576×320，保留一致的畫面比例。若更改其中一個通道，需確認兩者視野與裁切相同。

## 馬達校正：先空載，再裝支架

**預設 `MOTOR_CALIBRATED = false`，上電後自動控制暫停。** 這能先檢查畫面與 class ID，避免用尚未調好的行程直接頂住開關。馬達的停止脈寬也必須實測；1500 μs 只是起點。

序列埠輸入以下單一字元即可，換行符號會被忽略。動作期間不接受新的測試行程，停止指令始終優先。

| 字元 | 功能 |
|---|---|
| `n`、`x`、`d` | 立即輸出中立脈寬、取消動作並暫停自動控制 |
| `+` / `-` | 暫停且靜止時，將停止脈寬增加／減少 5 μs，範圍 1400–1600 |
| `j` | 暫停時，按 `OPEN_US` 方向短轉 280 ms，然後停止；不自動回程 |
| `k` | 暫停時，按 `CLOSE_US` 方向短轉 280 ms，然後停止；不自動回程 |
| `o` / `f` | 已標記校正完成且暫停時，測試開／關單方向轉動 280ms 後停止 |
| `a` | 校正旗標為 true、Wi-Fi 正常、推論新鮮且馬達靜止時，啟用自動控制 |

1. 拆下伺服臂，在 `n` 後觀察是否仍轉動；用 `+`／`-` 微調到停止。網頁「停止脈寬」會顯示目前數值。若仍會緩慢爬行，需調整馬達自身中立點（若實物有調整器）或改用更精細校正值。
2. 將這個數值抄回 `STOP_US`；序列埠微調只存在 RAM，重啟不保存。`OPEN_US`、`CLOSE_US` 必須在新的停止值兩側，不能相等。
3. 用 `j`／`k` 確認方向。方向相反就交換兩個脈寬。短轉仍可能超出機構可用行程，先空載測試。
4. 斷馬達電、在停止位置安裝雙向撥桿。先設定較短的 `OPEN_MS`、`CLOSE_MS`，確定剛好能撥開／撥關。目前開／關時間各為 280ms，兩方向可分別調整；本版不自動回程。
5. 脈寬與行程經過初步測量後，設定 `MOTOR_CALIBRATED = true`、重新燒錄。在暫停狀態用 `o`／`f` 驗證完整行程；發生異常立即 `x`。任何單一旋轉階段上限預設 500 ms。
6. 多次測試開／關行程、位置漂移與手動操作是否受阻。完成後輸入 `a`，先清空 ROI 至少 0.5 秒，再做手勢。

`x` 透過序列埠要求軟體停止，不能取代實體切斷馬達電源；若控制板本身失效，軟體無法保證中止 PWM。

## 辨識與防誤觸規則

- 全畫面跑 NN，再用**程式 ROI**過濾；未使用 `configRegionOfInterest()` 裁圖。因此框與 ROI 都採同一組全畫面正規化座標，不需要把裁圖座標換回去。
- ROI 預設為 X=20%–80%、Y=15%–85%，在 `Config.h` 修改。
- `configThreshold(0.35, 0.45)` 保留較低分的模型輸出作為模糊目標阻擋；真正可控制的框必須 **score ≥ 75**。
- ROI 內只能有一個相交的偵測框，該框必須完整落在 ROI，且 class 是 0 或 4。
- 手勢 2、3、4 不會動馬達；它們出現在 ROI 內也不能拿來解鎖。此處「關掉」是停用它們的控制功能，不會修改模型權重。
- 相同有效手勢至少維持 **1000 ms**、至少三筆新推論資料，才發出一次命令。切換手勢、低信心、框跨 ROI 或多個框，持續計時會重置。
- 每次命令後，需 ROI 無任何模型偵測框至少 **500 ms**，且距上次命令至少 **2000 ms**，才可重新判定。重啟及啟用時也要先離區。
- 若相鄰新推論超過 **800 ms**，持續判定與離區計時作廢；資料超過 **1500 ms** 未更新，或 Wi-Fi 斷線，則停止已啟用的自動動作、暫停自動控制。恢復後需重新 `a`。
- 空畫面、推論停止及 HTTP 網頁更新不能累積成有效手勢。

這些規則只能基於模型輸出判斷，無法保證偵測出所有手、遮擋或黑暗情況。若手完全漏偵測，程式可能視為空 ROI；環境光、模型準確度與機械結構都需要實測。

## 網頁與狀態的意義

板子提供 `GET /`（監看網頁）、`GET /api/status`（JSON）、`GET /frame.jpg`（JPEG）。HTTP 沒有馬達控制端點。網頁包含 ROI、所有保留的偵測框／class ID／分數、持續時間、啟用狀態、停止脈寬、最近指令、最近 12 筆事件，以及 JSON 匯出。

影像與辨識分別更新，**不是同一幀同步疊圖**，手快速移動時框可能略有落後。沒有實際燈光回授，所以「開燈指令已送出」與「馬達行程完成」都不表示已驗證燈亮。事件時間是板子開機後毫秒數；沒有 RTC/NTP。事件保留 RAM 最近 12 筆，重新上電即清除。需要完整長時間紀錄時可另擴充電腦端持續收集 JSON。

本機直接開 `web/index.html` 只能檢視版面，沒有板子 API 會顯示連線中斷；實際使用請開板子 IP。頁面無第三方腳本、雲端服務與外部字型。此 HTTP 監看服務沒有登入或 TLS，只應放在可信任的區域網路，不做路由器外網轉發。
